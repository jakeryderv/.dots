# bat

Configuration and carbonfox theme for [bat](https://github.com/sharkdp/bat).
Deployed to `~/.config/bat/`.

On Debian/Ubuntu the binary is **`batcat`** (the `bat` name is taken by another
package); `_bash/aliases.sh` handles the alias. The config directory is
`~/.config/bat` either way.

## Why this package exists

bat's default theme is Monokai Extended, which has nothing to do with
carbonfox. More importantly **git-delta reads bat's theme registry**, so one
theme file fixes syntax highlighting in two places:

| Consumer | Reads |
| --- | --- |
| `bat` / `batcat` | `--theme` in this config |
| `delta` (git pager) | `syntax-theme` in [`git`](git.md)'s `.gitconfig` |

## The theme file

`themes/carbonfox.tmTheme` is generated by
[nightfox.nvim](https://github.com/EdenEast/nightfox.nvim), which exports the
carbonfox palette to a Sublime/TextMate theme (`extra/carbonfox/` inside the
installed plugin).

**Note:** the upstream export carries leftover metadata from the Catppuccin
template it was generated from — the `name`, `semanticClass`, `uuid`, and
`author` fields all said "Catppuccin Macchiato" even though every colour value
is carbonfox. Those four fields are patched in the copy here so bat registers
the theme as `carbonfox`. Re-check them if you ever regenerate the file.

## Activate

```bash
cd ~/.dots
just apply bat
batcat cache --build     # required: compiles themes/ into ~/.cache/bat
```

The cache build is **not** optional — until it runs, `--theme="carbonfox"`
silently falls back to the default, and delta's `syntax-theme = carbonfox`
does the same. Re-run it after changing anything in `themes/`.

Verify:

```bash
batcat --list-themes | grep carbonfox
delta --show-config | grep syntax-theme
```

## Notes

- `~/.cache/bat` is generated state and is not tracked here.
- The theme only affects **syntax highlighting**. bat's frame, line numbers,
  and delta's diff colours come from the terminal palette, which
  [`ghostty`](ghostty.md) supplies.
